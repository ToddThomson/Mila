# Data Directory

This directory contains datasets, models, and tools for Mila. The structure is a reference scaffold — tracked in git so new contributors can copy it and populate it locally.

## Structure

### `/Datasets`
Training and evaluation datasets. Each dataset follows a standardized layout:
- `raw/` - Original, unprocessed corpus files (immutable source of truth)
- `encoded/` - Tokenized binaries generated by the Mila tokenize tool (derived, not tracked in git)
- `vocabularies/` - Tokenizer vocabulary files (`.bpe.mila`, `.char.mila`)

**Current Datasets:**
- `Shakespeare/` - Shakespeare text corpus

### `/Models`
Pretrained model weights in Mila binary format. Produced by the converters in `Mila/Tools/Converters/` — not tracked in git. Generate locally by running the appropriate converter.

**Current Models:**
- `Gpt2/` - GPT-2 weights
- `Llama/` - Llama 3.2 (1B, 3B) and Llama 3.1 (8B) weights and tokenizer

**Planned:**
- `Qwen3/` - Qwen 3 variants (Beta.1)
- `Mistral/` - Ministral variants (Beta.2)

### `/Tools`
Executables for data processing. Built automatically by the Mila project build.
- `tokenize.exe` - Tokenizes raw datasets into Mila encoded format

## Workflow

1. **Dataset Preparation**: Place raw data in `Datasets/<name>/raw/`
2. **Vocabulary Creation**: Generate tokenizer vocabularies and store in `Datasets/<name>/vocabularies/`
3. **Tokenization**: Use the tokenize tool to produce encoded binaries in `Datasets/<name>/encoded/`
4. **Model Conversion**: Run converters from `Mila/Tools/Converters/` to produce weight binaries in `Models/`

## Notes

- Vocabulary files use the `.mila` extension with a tokenizer-type prefix (e.g. `shakespeare.bpe.mila`)
- All model binaries are gitignored (covered by the global `*.bin` rule)
- Ad-hoc testing scripts live in `Dev/Scripts/` — not tracked in git
